# 本地数据文件说明

这个目录把原来嵌在 `summary_v6.html` 里的大数据拆成多个本地 JS 数据文件。页面通过 `<script>` 动态加载，所以仍然是本地文件方案，不依赖服务器、数据库或接口。

## 文件结构

- `customer_daily_stats.js`: 客服每日统计表，首屏加载。
- `review_details.js`: 差评评价明细表，点击客服后加载。
- `chat_index.js`: 聊天记录索引表，点击差评证据后加载。
- `chats/chat_*.js`: 单条差评对应的聊天记录文件，点击具体差评后按需加载。
- `attribution_results.js`: 问题归因结果表，预留给后续人工确认或 Agent 优化。
- `meta.js`: 原始生成信息和字段映射信息。

## 客服每日统计表

来源：`merged_table`

粒度：`date + agent`

用途：首屏总览、每日趋势、客服排行。

主要字段：

- `数据日期` / `鏁版嵁鏃ユ湡`: 统计日期。
- `客服` / `瀹㈡湇`: 客服账号。
- `咨询量`、`接待量`、`评价量`、`好评量`、`差评量`: 基础服务量和评价量。
- `即时满意度` / `即时满意度_pct`: 当前满意度展示和计算字段。
- `平均响应时长`、`首次平均响应时间`、`解决率`: 服务质量字段。
- `转接咨询量`、`转接接待量`、`转接满意率`、`非转接咨询量`、`非转接满意率`: 转接与非转接口径。
- `24H下单金额`、`促成下单商品金额`、`促成出库商品金额`: 转化与成交金额字段。
- `source_table`: 固定为 `merged_table`，便于追溯来源。
- `grain`: 固定为 `date + agent`，说明数据粒度。

## 差评评价明细表

来源：`anomaly_session_details`

粒度：一条低满意度或差评评价记录。

用途：点击客服后展示该客服在当前日期范围内的差评明细。

主要字段：

- `review_id`: 页面内部使用的评价记录 ID。
- `chat_key`: 连接聊天索引和聊天文件的键。
- `chat_file`: 对应聊天文件路径。
- `咨询时间`、`客服`、`顾客`、`满意度`、`是否解决`: 差评基础信息。
- `商品名称`: 评价关联商品。
- `cid`、`转接cid`: 会话匹配字段。
- `问题归因_一级`、`问题归因_二级`: 当前已有归因。
- `匹配方式`、`关联会话数`: 聊天匹配结果摘要。

## 聊天记录表

来源：`chat_lookup`

粒度：会话 / 消息。

用途：点击某条差评的聊天证据后，只加载这一条差评对应的聊天全文。

连接方式：

- 先用差评明细里的 `chat_key` 查 `chat_index.js`。
- 再按 `chat_file` 加载 `chats/chat_*.js`。
- 聊天文件中保留 `当前会话`、`关联会话`、`messages`、`source_log`、`message_count` 等字段。
- 查找时优先使用 `cid`，也可结合 `客服`、`顾客`、`咨询时间` 做兜底匹配。

## 问题归因结果表

来源：现有差评明细中的归因字段。

用途：给后续 Agent 或人工复盘写回归因结论，不影响当前页面展示。

主要字段：

- `attribution_id`: 归因记录 ID。
- `review_id`: 关联差评评价明细表。
- `cid`、`agent`、`customer`、`consultation_time`: 归因对象。
- `issue_level_1`、`issue_level_2`: 当前归因结果。
- `attribution_source` / 归因来源：当前固定为 `existing_field`，后续可写 `agent`、`human` 等。
- `confidence` / 置信度：预留数值字段。
- `human_confirmed` / 是否人工确认：预留布尔字段。
- `improvement_suggestion` / 优化建议：预留文本字段。
- `created_at` / 创建时间：首次生成时间。
- `updated_at` / 更新时间：后续更新归因时刷新。

## 后续接 Agent 的方式

Agent 不需要改 HTML。只要读取 `review_details.js` 和对应的 `chats/chat_*.js`，产出或更新 `attribution_results.js` 里的归因来源、置信度、是否人工确认、优化建议、创建时间、更新时间即可。
